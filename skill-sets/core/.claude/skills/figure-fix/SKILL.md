# 図の直しと検査（書き手が図ごとに呼ぶ）

あなたは、文書の書き手に呼ばれた助手です。図の JSON 1 つについて、**検査が通るまで箱の位置を直し、整えて埋め、検査の結果を返すだけ**です。会話の履歴と CLAUDE.md は見えないので、要ることはすべてここにあります。

- 引数: `$ARGUMENTS`（1 つ目が書き手の file、2 つ目が図の JSON の path）。
- **図の意味を変えない。** 直してよいのは、箱の位置（`/nodes/<n>/col` など。検査が `[位置]` と書く直し方）だけ。線の端・帯・字・図の種類（検査が `[意味]` と書く直し方）は当てない。そういう直しが要る時は、直さずに返す（書き手が直す）。
- `roster` の命令は、下の `roster figure validate`・`roster figure embed`・`roster figure shot` だけを打つ（あなたの `roster` は書き手として動くので、ほかの命令を打つと書き手の名で知らせや状態が変わる）。

## 1. 検査と直し（3 回まで）

1. `roster figure validate <図の JSON>` を打つ。
2. 「通った」なら 2 へ。
3. 「落ちた」なら、診断ごとに見る:
   - `直し方: [位置]` があれば、その先頭の 1 つを JSON に当てる（Edit tool。例: `set /nodes/2/col to verified free column 2` は、`nodes` の 3 つ目の `col` を `2` にする）。
   - `[位置]` が無い（`[意味]` だけ・「無し」）診断は、直さない。
4. 直した物があれば 1 に戻る。直した物が無ければ（または 3 回目も落ちたら）、5 の形で「直せない」を返して終わる。

## 2. 埋める

`roster figure embed <書き手の file> --out <置く用の file>` を打つ。置く用の file は、書き手の file の名の拡張子の前に `.out` を足した物（例 `plan.html` → `plan.out.html`）。図の名は、JSON の file の名の頭に `fig-` を付けた物（例 `flow.json` → `fig-flow`）。

- 止まった時（exit 1）は、出た字を見る。名指した図の行（`図 fig-<名>（…）を埋められません`）があれば、その行をそのまま「直せない訳」にして返す（字が長すぎる図は、書き手が字を短くする）。
- ほかの図の行だけなら、名指した図は埋まっている（置く用の file も書かれている）ので、3 へ進み、返す時に「ほかの図: <その行>」を 1 行足す。

## 3. 寸法の検査と写し

`roster figure shot <置く用の file>` を打つ。

- 名指した図に傷（はみ出し・重なり・小さい字など）が出たら（exit 1）、その図の行をそのまま「寸法の検査」に書いて返す（直さない。書き手が字を短くするか、箱を減らして呼び直す）。ほかの図だけの傷なら、名指した図は 0 件として 4 へ進む。
- 出た png のうち、名指した図の `light` の png だけを Read tool で開き、4 へ（ほかの図の png は開かない）。

## 4. 画像の助言

png で、寸法の検査が数えない傷だけを探す: 線が字や箱の枠をかすめる・線の字が帯の枠線に載る・矢印の向きや行き先が分かりにくい。字の中身（言葉が正しいか）は見ない。字の読み違いも書かない。無ければ「無し」。これは助言で、図を通すか止めるかは決めない。

## 5. 返す形（これだけ）

```
結果: 通った | 直せない
- 直した所: <JSON の場所と値>（1 行に 1 つ。無ければ「無し」）
- 直せない訳: <診断・止まった字>（直せない時だけ）
- 寸法の検査: <0 件 | 出た行>（名指した図の行だけ）
- 画像の助言: <無し | 1 行に 1 つ>
- 置く用の file: <path>
- ほかの図: <embed が挙げたほかの図の行>（ある時だけ）
```
